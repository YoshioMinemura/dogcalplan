## 現在の基準状態

- GitHub PagesとSupabaseによる家族同期版を運用中。
- 認証はSupabase匿名認証。メール・パスワード・4桁PINは使わない。
- ホーム画面版で未参加の場合は、完全な招待URLを一度貼り付ける。参加後は保存済みセッションで自動同期する。
- 現在のローカル実装の表示名はバランスリキッド。1回24 kcal／管理水分23 ml。バランスリキッド18 mlと追加水5 mlで構成する。
- 普通の水はml、固形食はkcal・g・粒を入力し、時刻も指定できる（ローカル実装済み）。
- ボミットバスターは1日2回、初期06:00と12:00。予定時刻を変更可能（ローカル実装済み）。
- ローカル実装の保存schemaは5。本番は前回公開のschema4。今回の本番適用・公開は未実施。
- 過去イベントの18 ml／23 ml実績と過去日の設定は変更せず、新規日は通常セット23 mlで扱う。

### 2026-09-06 入力・同期不具合と画面分離

原因解析:
- 犬の名前は当日スナップショットから表示され、「明日以降に適用」の名前が当日に出なかった。同期状態通知も設定フォームを再描画して入力を失わせ得た。
- 前回schema4化で既定名と移行名を「通常セット」に変更していた。
- 編集・スキップ・Undoがダイアログを開いた時点のオブジェクトを保持し、同期によるstate置換後に古いオブジェクトを更新していた。
- 同期送信の完了でpendingを無条件に解除し、送信中に追加された変更を取りこぼし得た。競合応答にも送信開始時の古いstateを使っていた。
- 予定枠の再計算値と利用者のスキップ操作を同じ更新時刻で競合処理していた。表示による再計算も日次updatedAtを書き換えていた。

実装:
- 現在の名前表示、設定下書き保護、最新stateへのID再解決、同期中の追加入力保持、明示的な枠操作の個別マージ。
- 5画面、3種類の履歴、日付指定による介護履歴のページング取得。
- 固形食の単位換算と入力スナップショット、スープの量換算、食事と排泄の時刻編集。
- 薬の2時刻設定、投与回番号の対応付け、schema5移行、キャッシュv7。
- `202609060001_edit_health_event_time.sql`追加。既存migrationは変更していない。
